## fig_seed_variance.pdf

- **Script:** `src/visualization/plot_seed_variance.py`. It writes `paper/fig_seed_variance.pdf`, 5.5 x 4.6 in, with `bbox_inches="tight"`, so the page is 362.9 x 319.0 pt (5.04 in wide).
- **Data file read:** none. All values are hard-coded in the script:
  - `BENCH_META`, lines 30-50: grid size and (CLB, DSP, BRAM) per circuit. These match `baselines/*_traditional_resources.txt` (core `fpga_size`, requirements).
  - `inpool`, lines 70-77. The docstring says these are "recovered exactly from the three training logs via reduction% = (1 - exp(-best_reward))*100". Checked against the per-circuit `best_layout_coordinates_{circuit}_multi11_long_seed{7,42_v2,123}.txt`: every value matches the **seed-42 v2** run, not the older seed-42 v1 run. See `mismatches.md` for the pooled-number conflict.
  - `zeroshot`, lines 78-82: identical to `det_seed{7,42,123}_{circuit}.json` `adp_reduction_pct`, rounded to 2 decimals.
- **Font sizes in the original at 3.33 in (scale 3.33/5.04 = 0.661):**
  - table text 8.5 pt -> 5.6 pt
  - group labels 8 pt -> 5.3 pt
  - headers 8 pt -> 5.3 pt
  - x label 8.3 pt -> 5.5 pt
  - ticks 8 pt -> 5.3 pt
  - glyph legend 6.6 pt -> 4.4 pt

  All are below 8 pt.

### Regenerated version: `data_export/fig_seed_variance.pdf`

- **Script:** `data_export/tools/plot_seed_variance_8pt.py`. Run it inside `distrobox enter ubuntu-work` with `~/.venv/bin/python`.
- **Page size:** exactly 3.33 x 3.9 in, with no tight-bbox cropping. Placed at `width=\columnwidth` (3.33 in), 1 pt in the file is 1 pt printed.
- **Text:** every element is 8.0 pt: row labels, grid column, (CLB, DSP, BRAM) column, header row, x tick labels, x axis label, both rotated group labels, and the glyph legend. The script checks that all 117 text objects are >= 8 pt and inside the page. A 300-dpi preview is at `data_export/logs/fig_seed_variance_check.png`.
- **Data:** the same `BENCH_META`, `inpool`, and `zeroshot` dictionaries, copied verbatim.
- **Layout:** same structure.
  - Inline table on the left: Benchmark | Grid | (CLB, DSP, BRAM).
  - Strip chart on the right: 3 seed dots, min-max line, median tick, dashed zero line, and the extra zero tick on raygentop.
  - In-pool group above held-out, each sorted by median descending, with a dashed separator.
  - Rotated coloured group labels on the right, a header rule, and the glyph legend on top.
  - Same palette (`src/visualization/palette.py`).
- **Changes needed to fit 8 pt in one column:**
  1. Column x-positions are computed from measured text widths instead of fixed data coordinates.
  2. The x axis shows ticks 0/20/40/60 with range -6..74; the original had ticks 0..80 with range -85..94, most of it used by the table. All data points (max 69.08) are inside.
  3. The x-axis label is centred under the whole figure, because at 8 pt it is wider than the narrow axis.
  4. The glyph legend now reads "tick: median" instead of "|: median", so the bar glyph doesn't look like a separator. It moved to the top line, since at 8 pt it no longer fits beside the header.
  5. The group labels read "In-pool (trained)" / "Held-out (zero-shot)" on one line each, not two.

## fig_spree_timeline.pdf

- **Script:** `src/visualization/plot_spree_timeline.py`. It writes `paper/fig_spree_timeline.pdf`.
- **Data files read:**
  - `all_layouts_multi_seed_123_multi11_long_seed123.jsonl` (script line 41): the per-episode training log for seed 123. Best-so-far spree episodes come from here, and the panel % label is `(1 - exp(-best_reward)) * 100` (line 125).
  - `runs/spree_timeline/manifest.json` plus `runs/spree_timeline/milestone_XX/` (VPR `.place`, arch, constraints). These are generated by `scripts/run_spree_timeline_vtr.py`, which re-runs VTR on each milestone layout to get real placements. Panel grid size = VPR "FPGA sized to" in the re-run, including the IO ring.
  - `arch/k6_frac_N10_mem32K_40nm.xml` plus `runs/spree_traditional/` for the traditional panel.
- **Cross-check against the paper:**
  - milestone_14: `FPGA sized to 10 x 13`, reduction 39.106% -> "+39.1%" ✓
  - milestone_10: `11 x 12`, 36.915% -> "+36.9%" ✓
  - milestone_09: `12 x 11`, 33.312% -> "+33.3%" ✓

  The re-run of milestone_14 reproduces the training metrics exactly (routing area 520646, delay 10.0326 ns, power 0.008775 W; `best_layout_coordinates_spree_multi11_long_seed123.txt`).
